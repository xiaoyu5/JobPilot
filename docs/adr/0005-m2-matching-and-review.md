# ADR-0005：M2 证据匹配、话术审计与本地审核

日期：2026-10-22。状态：实施。基线：PRD v1.0 §7、§14、AT-01–AT-07。

M2 复用 M1 的唯一 Worker、专用 Chrome、事实快照和岗位池。真实 BOSS 访问继续使用 ADR-0004 原生只读接口。采集入口保持只读采集；新增独立 Dry Run，明确将必要 JD 和已确认事实发送给用户配置的模型，再生成草稿并加入本地审核队列。两种任务共用单任务守卫；模型并发固定为 1。

## 事实和模型边界

只有当前已冻结的已确认事实参与匹配。模型不接收原始附件、联系方式、Cookie、浏览器账户信息和事实来源文件名。按岗位技能关联排序，最多 50 条、18,000 字符的事实文本；JD 匹配最多 16,000 字符，话术阶段最多 6,000 字符。界面提醒 Cockpit 可能转发至远程模型。

兼容端点优先 Chat Completions JSON mode，400/422 时最多一次取消 response_format 重试。输出经本地严格 Zod 和引用校验，无效输出最多修复一次，总请求最多 3 次。输出未通过时保留 REVIEW 或 BLOCK；连接异常停止 Dry Run，保留进度。错误日志不包含模型原始响应或 API Key。实现参考 [OpenAI Structured Outputs 官方文档](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)：JSON mode 仍需要应用层 schema 校验。

strengths 的 reason 必须逐字引用对应已确认事实全文；未知 factId 或添加未经证实的个人能力描述视为无效响应。独立 P2P 协议栈/内核要求增加保守的硬缺口检查，不能用 SDK 集成替代。阈值 80/60 可配置，模型更保守的结论保留，硬缺口不能得到自动通过资格。

## 话术采用证据选择计划

为避免二次改写夸大经历，第二次模型请求选择 1–2 条完整已确认事实及中文礼貌开头/结尾。本机据此组成最终文案，不允许截断事实去掉“仅”“未”等限定。事实太长、隐私词、占位符、绝对化表述或无法满足长度时阻断，用户可先整理事实库。此策略比自由生成更保守，避免把语义审计误当成客观事实证明；后续可扩展经用户审核的精炼事实。

手动编辑记录版本和完整历史，重新进行事实/长度审计；只允许完整事实与明确的礼貌用语组合。新增经历应先在事实库确认。未保存修改不能标记已审核；保存编辑撤销此前本地审核。通过审计的草稿才能进入队列，队列只有 PENDING/REVIEWED/BLOCKED/STALE，不存在发送操作。

## 缓存、迁移和恢复

缓存包含岗位、JD 内容/哈希、简历版本、提示版本、模型/端点及匹配规则。事实变动、JD/关键岗位字段变动、模型设置或规则变化会使结果、草稿、队列审核失效。异步响应提交前重查上下文，防止旧响应覆盖新状态。失败输出保留审计记录但不缓存为成功结果，允许用户显式重新请求。

SQLite v1 → v2 使用事务迁移，保留已有岗位/事实/任务；迁移前通过 SQLite VACUUM INTO 创建权限 0600 的 jobpilot.pre-m2.sqlite（如尚不存在）。新增分析历史、草稿修订、本地队列表和任务计数。中断的采集、分析和生成任务重启后为 NEEDS_HUMAN，不自动续跑。列表分页限制在私有 IPC 的 1 MiB 范围内。

用户明确要求改用本机 `.env` 并在应用内修改 API Key，替代 M1 Keychain 方案。最终实现见 [ADR-0006](0006-env-credentials.md)：启动读取已选文件，Key 只在 Worker 内存，不回显和写入数据库；设置可加载文件、修改并原子保存。MCP 复用同一 Worker，不读取第二份凭据。

## 产品约束补充（用户 2026-10-22）

用户后续可能优化简历表达，项目经历和工作经历保持真实不变。GitHub 地址只加入附件简历，在线简历不加。JobPilot 完成后计划公开至用户 GitHub；此计划不构成现在创建仓库或发布的授权。附件改写、上传和发布不属于 M2，后续实施时沿用这些约束。当前 API Key、原始简历、Cookie、数据库、真实岗位快照和本机验证截图继续排除提交。

安装测试期间用户报告反复钥匙串提示及 App 消失，随后明确选择 `.env`。最终应用已移除全部 Keychain API 和依赖；发行测试不会创建钥匙串项目，旧项目留在系统中不读取也不删除。
