# ADR-0008：两条首次沟通及已有会话回复

日期：2026-10-22。状态：M3 增补实施；真实发送尚待有限验收。用户已确认首次“立即沟通”会发送平台默认招呼，选择“默认招呼后再发 AI 文案，共两条”，并要求区分已有沟通与已拒绝会话。本决策增补 ADR-0007；PRD v1.0 原文不修改。

## 首次沟通

“立即沟通”视为发送动作。最终确认展示平台默认招呼与精确 AI 文案两步，预占两条额度；只有已知目标身份、唯一主岗位入口、GUI 授权和全部门禁满足后才能点击。先确认默认招呼对应的服务端消息标识，再等待最小间隔并重新检查后发送 AI 文案。

0.4.4 对真实岗位 `.startchat-dialog` 的补充：此形状以绑定目标后的独立“已发送”状态作为可见回执，区别于完整聊天页的服务端消息 ID；不会把本机回执指纹称为服务端 ID。默认之后中断且 AI 尚未提交的记录，需要重新 GUI 确认才能仅继续 AI。适用条件和不可重试边界见 [ADR-0015](0015-start-chat-receipts-and-ai-followup.md)。

默认招呼的实际文字由平台控制，界面不承诺能预先修改它。“继续沟通”转入已有会话流程，不再次执行首联。推荐岗位入口不参与主岗位匹配。部分成功明确显示 1/2：默认招呼已发而 AI 未发时不重发默认招呼；结果不明锁定人工核验。两条消息分别计数，聊天回复占一条，共享每日额度、轮次、时段、最小间隔及急停。

## 已有会话

“会话助手”只导入当前选中的会话，不把侧栏联系人预览当作当前历史。按招聘人持久化拒绝状态；换岗位或后续消息不会自动解除拒绝。等待对方回复的会话不追问。历史不完整、身份/消息标识不可靠、意图不明时转人工；薪资、面试时间、联系方式、附件及其它承诺由用户处理。

有新提问时，模型仅选择已冻结确认事实的 ID；最终回复由原事实和受控礼貌表达组成，不新增经历或承诺。模型只能看到最新脱敏提问及必要事实，不接收联系人列表或聊天全文。这是对 ADR-0007 原“不发送聊天记录至 LLM”约束的必要、最小范围扩展。用户配置的模型服务仍可能将必要内容转发至远程。

自动回复是独立 GUI 开关，限定用户勾选的 1–20 个已导入会话，重启/配置变化/异常/急停撤销。每次回复重新读取当前历史及最新入站消息；拒绝优先于去重，发现拒绝立即停止。按招聘人 + 对方消息 ID 唯一去重，与首联的岗位/招聘人永久锁分别保存。写页面前持久化意图；不确定结果和重启中断均锁定，不自动重发。

## 原生读取范围

沿用普通专用 Chrome + Apple Events。除可见 DOM 属性和站内链接外，允许从**当前渲染元素及最多三层父元素**的 Vue `$props` / `$data` 中读取明确列举的岗位、招聘人、消息 ID 和历史分页完成标志；岗位必须绑定当前 URL 中的岗位 ID，聊天身份必须对应可见姓名。这是对 ADR-0007 全面排除前端内部状态的有限修订，落实 PRD §8.1 已加载页面数据读取范围。

不访问全局 store、认证/安全字段、Cookie 或本地存储，不递归遍历对象，不序列化组件状态，不请求私有 API。原生接口只运行随包固定脚本。未知结构停止；匿名夹具通过不能替代真实页面及真实发送验收。

真实环境排查确认 Apple Events 脚本运行在独立 JavaScript 环境，不能依赖页面自身附加的 Vue 标识；Chromium 的 [AppleScript 实现](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/chrome/browser/ui/cocoa/applescript/tab_applescript.mm) 使用 `ExecuteJavaScriptInIsolatedWorld`。因此组件元数据夹具通过不构成原生真实环境可用的证据。

为此准备了**可选、由用户手动加载和点击连接**的 [只读连接扩展](../../extensions/boss-reader/README.md)。按 Chrome 官方 [scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting) 与 [activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab) 模式，仅临时访问用户主动选择的当前标签页，固定脚本再次限定 BOSS 域名。它在 MAIN 环境读取上述有限业务元数据，为原生接口发布 DOM 标记；不联网、不读取 Cookie/认证字段、没有发送操作。断开恢复标记，刷新需重新连接。扩展未自动安装，不以连接代替发送授权；若真实组件字段仍不可用，继续保持身份不明门禁。

当前 BOSS [公开聊天页面脚本](https://static.zhipin.com/fe-zhipin-geek/web/chat-new/v5573/static/js/chat.4ee8f36f.js) 中，主会话 `.chat-record` 的 `history` 表示尚有更早记录，`isToTop` 在非空末页加载完成后才成立。只读连接仅在当前姓名和招聘人绑定一致、`history=false`、`loading=false`、`isToTop=true`、`msgMinId` 为正整数且最多 100 条已确认消息全部可见时发布历史完整标记。初始重置状态不满足条件；更长或尚未加载的历史保留人工核验。这里只读取当前渲染组件的分页标志，不调用脚本中的请求接口。

“立即沟通”后的默认招呼由平台以求职者方向发送，PK 卡为平台系统信息；方向不代表由用户手动编写。两者均不当作 HR 回复，未收到对方新消息时保持等待。当前真实会话中的这两条记录不是 JobPilot 发送。

0.3.2 的真实岗位诊断确认招聘人不透明标识可含 `~`，校验允许这个字符并保持原值；不放宽站点、岗位绑定或安全字段限制。聊天优先用当前组件的 UID；只记录同一组件明确提供的业务 ID 别名，拒绝与发送目标比较同时考虑这些已证实的别名。当前组件已绑定时不再让旧路由覆盖它；缺少组件绑定时路由仍不足以确认身份。相同招聘人姓名和公司命中拒绝记录时也保守阻断首联。

已有会话刷新可指定已导入的会话 ID，并在读取后再次校验目标。只读扩展从当前可见联系人组件的 `source` 中读取姓名及明确列举的业务 ID，只发布曾被用户逐个选中过的身份；不读取整个列表对象或隐藏联系人。切换优先点击唯一可见且名称仍一致的联系人，保留已连接的页面，不通过整页导航丢弃连接。联系人未显示、标识变化或虚拟列表复用时停止，既不猜测也不滚动加载所有联系人。

0.3.3 将同一已绑定组件明确提供的业务标识关系保留在本地会话快照中；后续读取字段变少不会删除已知关系。拒绝、首联永久锁、按入站消息 ID 的回复锁及已讲事实提示均沿这些已观察关系查找，支持通过中间标识关联到旧记录。姓名、公司、消息链接和模型输出不建立标识关系，也不扩大 Auto 的具体会话范围。已导入的同一招聘人会话会阻断再次首联，包括仅存在平台默认招呼的等待会话；已确认的回复或人工跳过锁不会因标识切换而失效。发送前仍要求当前会话 ID 和招聘人 ID 与计划目标完全一致，标识关联只用于保留历史与阻断重复。

## 开发版启动权限修复

实际系统日志显示，项目位于 Documents、配置引用项目 `.env.local`，且 ad-hoc 每次构建后的 code requirement 改变，导致文稿授权重询；直接启动 Chrome 时，其权限请求的 responsible application 又归为 JobPilot，包括 App Bundles 管理请求。

当前用户的运行副本移至 `~/Applications/JobPilot.app`，配置私密复制至原 Application Support 目录 `.env`，保留原配置不修改。Sidecar 工作目录设为数据目录；Chrome 通过 Launch Services 启动，再以专用 Profile 的进程锁和完整命令校验归属。没有授予 JobPilot App 管理权限，没有改写 Chrome 或系统权限库。发行签名、公证仍按约定留至 M4。
