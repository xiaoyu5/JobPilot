# ADR-0009：真实发送统一放在功能完成后的最终验收

日期：2026-10-22。依据：用户明确要求“真实发送最后再验收，全功能完成后匹配岗位点立即沟通后再测试发送”。

M3 的受控发送功能与匿名回归继续维护，真实账号发送不作为进入 M4 功能研发的前置条件。M4 先完成复盘统计、诊断导出、数据管理与恢复，以及打包和 MCP 回归；真实发送单独记录为最终验收项。

最终验收顺序：

1. 完成全部功能开发与隔离环境回归，正常安装最终候选版本。
2. 使用用户已确认、冻结的事实匹配真实岗位。候选达到当前阈值、无硬缺口，并通过目标身份、拒绝历史及去重检查。
3. 在应用内核对具体岗位、最终 AI 文案、默认招呼和两条消息额度，明确确认本次发送。
4. 点击“立即沟通”时即记为平台默认招呼的发送步骤；确认对应消息后，再测试已确认的 AI 文案。两步分别核验，部分成功及结果不明按原 Outbox 规则处理。
5. 已有会话回复和所选会话 Auto 的真实验收使用真实的新提问及独立 GUI 授权；已拒绝和等待会话保持原规则。

最终验收之前不点击真实“立即沟通”、不填写聊天编辑框，也不启用真实发送或任何 Auto。当前授权仍包括既有只读验证。后续 [ADR-0011](0011-github-dmg-distribution.md) 明确 GitHub DMG 分发，正式签名与公证为可选；干净环境继续待验收，实测记录齐备后才标为通过。
