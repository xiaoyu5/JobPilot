# ADR-0012：以完整 App 交付能力评估常规应用研发要求

日期：2026-10-22。用户明确补充：拥有多年 App 开发经验，可独立完整开发并发布上线；熟悉应用层工作，系统底层专项需要进一步核实。目标是争取匹配的面试机会。

## 决策

匹配评估实际岗位与能力关系，不要求简历逐字复述每项普通职责。已经确认的独立 App 交付经历可支持需求理解、开发文档、自测和普通迭代流程。缺少某项常规措辞或行为案例属于面试核对项，不直接作为硬冲突。

匹配提示版本为 `match-v2.2`。本地校准只对有已确认完整 App 开发及上线事实的用户生效，只将纯常规流程的硬缺口降为软核对项，不提高原分数，不强行改变模型的保守决定。混合了具体技术、后端、系统底层、商业年限、资质、语言或团队管理要求的条目不作此调整；明确相反的事实继续保留。P2P 内核/协议栈边界仍由独立规则保护。

通用应用层经验不自动展开为所有框架精通、Flutter 多年主开发、Android 正式工作年限、DevOps 流水线建设、后端架构或内核研发。招呼语优先展示相关技术、项目或完整 App 交付能力，仍只使用已确认事实原文，不创造履历或成果。

## 用户补充与审核

新增 `resume.add` 及“补充一条真实事实”表单，来源为“用户补充 / text”，保存原话或本人输入。新条目默认待审核；编辑仍撤销确认和冻结。事实与提示版本变化使旧匹配、草稿及审核失效。

本次用户在对话中已经明确确认了基础应用研发及上线能力，可据这次直接自述补充并确认相应事实，来源保留对话上下文，不再要求为这些基础能力逐项提供项目案例。原有工作、项目、日期与成果不改；未获本次确认的其他能力仍按原审核流程。

事实确认不授予真实发送或 Auto。最终岗位和文案仍需在 GUI 核对确认。
