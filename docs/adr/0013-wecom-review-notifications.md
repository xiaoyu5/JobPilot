# ADR-0013：企业微信单向待办通知

日期：2026-10-22。状态：已实现，0.4.3。

用户要求参考 get_jobs，在需要审核时通知企业微信，并了解是否仅提醒手机端查看 BOSS。

参考 [get_jobs 的 Bot.java](https://github.com/loks666/get_jobs/blob/main/src/main/java/com/getjobs/worker/utils/Bot.java)：读取 `HOOK_URL`、`BOT_IS_SEND`，向群机器人 Webhook POST `msgtype=text`。这是主动推送文本的实现；该类没有消息接收回调或远程审核操作。JobPilot 独立实现此协议，不引入其源码。

## 行为

默认关闭，在“设置 → 企业微信通知”保存机器人地址并启用。支持三类提醒：

- 真实 BOSS 岗位的首联草稿 PENDING / BLOCKED / STALE；已审核、已有发送意图及匿名演示不提醒。
- 已读取会话的 REVIEW，或未纳入聊天 Auto 的 REPLY_NEEDED；拒绝和等待状态不提醒。按会话与最新对方消息去重，重复扫描不重复提醒。
- 首联或回复 Outbox 的 NEEDS_VERIFY，以及各类最近一次真实任务的 NEEDS_HUMAN。已被新任务取代的历史异常不当作当前待办。

Worker 运行时每五秒检查本机 SQLite 状态，不为通知额外读取浏览器。将变化合并为数量摘要，相同版本成功后不再通知，回执以摘要哈希保存，重启后仍去重。测试与待办通知共用至少一分钟间隔；超时或失败最多自动尝试三次，用户可在设置中手动再检查。通知失败不改变业务状态，不自动重试 BOSS 发送。请求已被服务端接收但本机未取得回执时，后续通知仍可能重复，Webhook 不提供端到端恰好一次保证。

通知包含数量、处理位置和固定 BOSS 消息页链接，不包含公司、招聘人、岗位标识、简历、文案、聊天正文或凭据。手机企业微信接收群消息；用户自行在手机 BOSS 查看消息或回 Mac 的 JobPilot 审核。没有手机远程批准、回复回调或新增公网服务。会话提醒仅覆盖已读取状态与已有授权的聊天 Auto 扫描，不宣称实时监听整个收件箱。App 退出、Mac 休眠时不检查。

## 配置与权限

Webhook 存在当前 `.env` 的 `WECOM_WEBHOOK_URL`，兼容 `HOOK_URL` 回退；应用可修改、清除，留空保留，密钥不回显或写入数据库。仅接受企业微信官方 HTTPS 主机的固定群机器人发送路径和一个 key，禁止重定向。响应除 HTTP 状态和数值错误码外不透传，不把地址、key 或第三方错误正文写入诊断。

保存、测试和手动检查要求现有 GUI capability；MCP 十个工具不变，不添加通知或发送授权工具。通知开关与 BOSS 真实发送、两种 Auto、时段和额度彼此独立。配置变化会中止在途通知；改地址须重新保存，恢复备份后默认关闭并清除目标绑定。本机重置会清除设置及受管理的 `.env`。

## 验证

验证记录见 [0.4.3](../m4.3-validation.md)。匿名测试覆盖真正的草稿编辑撤销审核、按版本与消息去重、拒绝排除、Auto 范围、HTTP/API/网络失败与限流、并发/退出、环境配置及恢复、GUI 权限和 BOSS 状态隔离。真实手机收件需用户配置自己的机器人后测试，不能以模拟请求替代。
