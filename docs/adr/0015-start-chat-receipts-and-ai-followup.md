# ADR-0015：真实岗位弹窗回执与单条 AI 续发

日期：2026-10-23。状态：0.4.4 实现，真实结果见 [验证记录](../m4.4-validation.md)。

首次实测点击“立即沟通”后，页面出现 `.startchat-dialog`：包含招聘人标题、平台默认招呼、“已发送”回执、文本编辑框和微信订阅二维码。旧适配器没有识别此形状，按既定策略停止并保存 NEEDS_VERIFY；用户截图确认默认招呼已经发出，AI 尚未提交。二维码是回复通知订阅，与求职消息发送无关。

弹窗身份必须同时满足当前岗位 URL、主岗位唯一沟通入口中的官方聊天目标，以及弹窗招聘人标题与岗位招聘人一致。只在对应消息的独立状态节点明确显示“已发送”时确认回执；发送中、失败、姓名不符、其它弹窗和推荐岗位均不能通过。完整聊天页仍沿用原消息 ID 方案。此弹窗没有服务端消息 ID 时，使用明确标注 `visible-receipt:` 的本机内容/位置/目标指纹关联多次 DOM 读取，不将其伪称为服务端 ID；不能据此认定整段聊天历史完整。

本次默认招呼确认后可在同一真实弹窗填写并提交已批准的 AI 文案。编辑框、唯一可见发送控件、禁用状态、事实/目标/最新消息、拒绝及持久化提交阶段仍逐步检查，不调用站点请求接口。

已经停在默认招呼之后的记录，不自动继续，也不重新首联。新增“检查仅续发 AI 文案”只读入口：只有原记录证明 AI 从未进入 CLICK_DISPATCHED、原文案/事实/规则/目标不变、没有其它不确定记录，且当前默认招呼可重新确认时，才给出独立的一条 AI 确认窗口。用户必须再次在原生 GUI 确认。它保留原 Outbox、去重锁及原两条额度，不增加轮次，不重发默认招呼，也不启用 Auto 或解除全局急停。

续发使用单次、五分钟、上下文绑定的计划及独立持久授权。新的急停使计划失效，执行期间继续响应取消、休眠/时钟跳变、时段、模型健康、事实、目标和拒绝变化。AI 一旦进入提交阶段，即使返回未知，也不能通过续发入口重试。一般已发、人工跳过或原始文案变化的记录同样不能续发。

匿名测试覆盖匹配真实形状的弹窗、明确回执和未发送状态、招聘人不符、默认一次与 AI 一次、GUI 权限、原意图/额度/轮次、计划复用、急停和 AI 点击后不确定结果；另有真实界面确认窗口及暗色窄屏验证。匿名通过不替代实际页面确认。
