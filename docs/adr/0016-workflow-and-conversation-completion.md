# ADR-0016：会话、文案、任务和搜索收尾

日期：2026-10-23。依据：用户要求按已有会话、自然文案、任务串联、搜索采集的顺序补齐缺口。原始需求保持冻结，本决策补充实现范围，不把匿名回归视为真实发送授权。

## 已有会话

只读扩展 0.2.0 从当前可见联系人组件的 `source` 读取明确列举的业务 ID 和姓名，姓名一致且身份唯一才发布 DOM 标记。相对 0.1.2，不再要求事先逐个手动选中。权限仍是 activeTab + scripting，无网络、Cookie、存储、后台权限或发送操作。

原生接口可滚动正常联系人列表，最多 10 次、100 个可靠目标；每批轮换读取最多 10 个。读取聊天时可向上滚动历史，最多 8 次、100 条；完整性仍必须由真实组件标志确认，超限/未加载完转人工，不能凭超时推断完整。连续多个未答问题或此前未答的薪资等事项也转人工。只读扫描不会产生回复意图，不将新联系人加入 Auto。

用户可在 GUI 开启每 30 秒的只读监测，重启、急停、页面/连接异常后关闭。所选会话 Auto 的 1–20 个范围、按入站消息去重、拒绝锁和独立授权保持。岗位池的“继续沟通（不发送）”只允许点目标一致且文本精确为“继续沟通”的入口；“立即沟通”不符合该操作。

## 自然文案

新增 `rewrite` 方式，允许模型精炼 1–2 条已确认事实。每句保留 factId 与完整原事实；限制新增数字及删除能力限定，并独立请求证据核对。此检查不代表语义绝对正确，生成结果始终需要用户逐句审核。Auto 不会发送未经人工标记的精炼草稿。编辑不能自行换入未经核对的改写句，需重新生成或使用已确认完整事实。

传统 `natural` / `concise` 方式仍保留。连续预览界面默认自然精炼；选择 Auto 时使用完整原文事实，后端拒绝 Auto + 未审核自然精炼的组合。事实库与历史批准记录不因新增功能被自动修改。

## 连续任务与排程

`workflow` Run 串联搜索、逐条 JD、匹配、草稿和入队。每步在现有 checkpoint_json 中持久化岗位集合、索引、事实/配置指纹及搜索方案快照；恢复先核对上下文。已读 JD 和已完成匹配不从头重做。发送仍交给原有 SendingService，Auto 子任务只接收本次产生的队列 ID；不会夹带其它待发队列。子任务不确定或中断后保留原意图，不能重新开启首联。

每日排程由 GUI 设置时间、时区、方案、文案方式及预览/Auto 模式。每天触发前先记录本地日期，避免重启或时钟重复触发；仅当前进程存活期间启用。重启、明显休眠/时钟跳变、急停后停止，不唤醒、不跨日补跑。Auto 仍需独立授权，排程和 MCP 无权开启它。

## 搜索方案与分页

保留 primary 默认方案，可另存、切换、删除方案，最多 20 个。MCP 只读搜索接受保存的方案 ID。旧数据库无需变更结构，原方案与 v5 私密备份兼容。

每方案设置最多 50 条岗位、1–10 页、每页 1–20 次滚动。只点正常页面中唯一、启用的下一页；链接必须属于当前搜索页且不改变筛选条件。分页后须观察卡片更新；没有下一页则结束，歧义或状态改变则停止。跨页按岗位 ID 去重。不调用私有接口、不构造站点签名、不绕过校验。
