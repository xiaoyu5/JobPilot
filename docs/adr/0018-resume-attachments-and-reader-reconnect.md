# ADR-0018：人工同意附件发送与只读连接恢复

日期：2026-10-23。用户明确要求“人工处理附件请求选同意就直接发送附件简历”，取代 ADR-0017 中同意后仅发文字的处理。用户同时报告所有会话的只读刷新均报 CHAT_NOT_VISIBLE；本机只读检查确认已登录、当前身份无法绑定，实际是页面连接失效。

同意对应 `boss-uploaded` 附件操作，不把占位文本写入编辑框。用户在 GUI 核对当前请求后独立确认，使用 BOSS 索取卡片中的同意入口；若出现附件选择窗口，只发送唯一附件或界面明确选中的默认版本，不猜选第一个。此实现不读取本地简历文件、不调用私有接口、不交给模型决策。拒绝仍可发送固定文字。旧版同意文字计划失效，已处理请求等待，不补发。

附件与文字共用持久发送意图、请求 ID 去重、当前身份及完整历史、最新消息、规则和时段、急停及五分钟确认。提交之前持久化，GUI 以外及 Auto 不能代为同意。只接受请求之后新增、非基线、带服务端消息标识且有送达/已读回执的本人附件卡片；选择窗口中的文件名也必须一致。结果未知或操作中断时进入待核验，不自动重试。

可见附件选择窗口的结构参考[公开实现](https://github.com/powerycy/BossHunter/blob/main/src/bosshunter/executor/monitor.py)，仅用于了解页面交互，不采用其乐观送达推断，也不复制其实现代码。真实页面兼容性与真实送达需分别验收。

读取旧记录前，从本机已绑定会话的明确别名关系补齐导航标识，避免旧记录只持有不再用于列表定位的标识。只读切换按组件明确列举的招聘人 ID 别名和姓名绑定，岗位冲突仍阻断；不解码或猜测标识。消息页没有选中会话时也在页面层发布连接状态与可见联系人标记，避免必须先手动点一个联系人的循环；应用显示连接状态和可见联系人数。连接失效立即提示 CHAT_READER_REQUIRED，不再先滚动查找并误报联系人不存在。目标确实不在已连接的有限列表中仍为 CHAT_NOT_VISIBLE。

扩展 0.3.0 默认保持 activeTab / scripting 手动连接。用户可自行点击“记住只读连接”，经 Chrome 可选 BOSS 网站授权后，注册仅匹配消息和岗位页的 MAIN 环境只读脚本，跨刷新及重启保持。没有后台、网络、Cookie 或发送操作。断开时注销并撤销网站授权；拒绝额外授权仍可使用单次连接。应用不自动安装、重载扩展或批准此权限。
