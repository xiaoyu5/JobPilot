# ADR-0019：默认招呼后的只读核验与原文恢复

首次沟通弹窗可能使用不同的招聘人业务标识，严格核验会停止；完整聊天页能够通过只读连接给出同一招聘人的 UID 与加密别名。不能以姓名相似或页面仍为同一个岗位来放宽发送身份判断。

默认招呼核验失败或结构无法绑定时，只允许刷新原岗位，并点击明确的“继续沟通”。该路径不得点击“立即沟通”。进入完整聊天页后，仍使用原岗位及原招聘人标识核验，要求当前绑定别名包含原标识，并取得唯一的已送达默认消息；未知、拒绝或其他消息出现时不追加 AI。导航等待有上限，最多一次回退。

结果未知保留原发送意图和两条额度。若原 AI 从未提交，用户可在界面独立确认只恢复这一条。已沟通状态刷新可能使原队列失效，因此恢复专用验证重新计算原始未联系时的上下文，核对 JD、标题、公司、城市、薪资、冻结事实、模型及匹配规则，重新审计同一文案。只有联系状态允许不同；原发送规则、草稿版本、接收人及内容仍须与意图完全一致。

此路径不复活失效缓存，不授予新首联权限；AI 已点击但结果未知、事实或 JD 改动、拒绝、急停上下文变化均不可绕过。新确认只能来自原生界面，普通 IPC 与 MCP 无权批准。

文案准备还需等待异步渲染的发送按钮就绪。相同意图轮询不重复写入输入框；超过上限仍不就绪时停在提交之前。首联和已有会话采用相同的准备就绪契约。
