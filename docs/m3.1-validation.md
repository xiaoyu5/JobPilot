# M3 会话增补验证记录

日期：2026-10-22。版本：0.3.1，ARM64。设计见 [ADR-0008](adr/0008-existing-conversations.md)。本轮实现两条首次沟通及已有会话受控回复，真实账号保持发送关闭。首个实测会话的招呼及 PK 卡均由平台在“立即沟通”后生成，未发现 HR 回复，不计为用户手动发送或 JobPilot 发送。

## 行为与匿名验证

- 首次沟通确认两条：平台默认招呼确认后再发 AI 文案；预占两条额度，独立计数，部分成功不会重发第一条。“继续沟通”不作为首次沟通入口。
- 当前会话独立识别：已拒绝持续停止；最后一条为求职者方向消息（含平台默认招呼）则等待；PK 卡是平台系统信息；对方有新提问才准备事实回复；历史或身份不明、薪资/面试/联系方式等转人工。
- 自动回复单独 GUI 授权并限定会话；按对方消息 ID 去重。发送前再次检查拒绝及新消息，未知结果锁定人工核验。与首联共享限额、时段、间隔、浏览器互斥及急停。
- 模型仅选择已确认事实 ID；不发送聊天全文或联系人列表。凭据继续由可编辑的本机 `.env` 提供，不使用钥匙串。

TypeScript、**58/58 自动测试**及 Worker/UI 生产构建通过；回复中断恢复测试验证 NEEDS_VERIFY、拒绝重试、授权撤销和急停。可选只读连接测试使用真实 Chrome 的两个隔离 JavaScript 环境，验证未连接时无身份、连接后仅共享当前业务标识、拒绝卡片可读、断开恢复原 DOM，以及真实形状的分页完成标志不会与初始状态混淆。匿名测试使用临时库与本机模型夹具，DOM 测试拦截全部页面。原 M1/M2/M3 UI 回归及 `verify:ui:chat` 通过，包括两条首联确认、三类历史会话区分、精确回复确认、指定会话 Auto、去重、拒绝停用、急停、暗色与窄窗。

真实只读核验发现并补入两项回归：默认招呼后的 PK 卡是系统信息；“经验不完全一致”加求职祝福的委婉拒绝不能按“经验”关键词当作新提问。另以真实消息结构补测 `.text` 中的“已读”回执与 `.text-content` 正文，消息核验只比对正文。没有通过测试脚本向真实账号发送消息。
