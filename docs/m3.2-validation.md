## 本轮改动

- 真实岗位的官方聊天跳转中，岗位 ID 与当前详情页一致，招聘人 ID 长度为 28 且包含 `~`。旧校验误判为无效；新校验保留该 URL 安全字符，不解码、不读取安全参数、不访问私有接口。岗位与站点绑定保持严格。
- 当前聊天组件优先使用 UID；同一组件明确给出的其他业务 ID 才记为别名。跨别名保留拒绝状态，首联也检查拒绝别名；姓名和公司均匹配已有拒绝记录时保守阻断，不用这些信息授权任何发送。
- 只读扩展 0.1.2 只为用户逐个选中过的身份发布可见联系人定位标记，且核对该联系人组件的姓名和业务 ID。未知联系人、虚拟列表复用、同名但 ID 不同或节点消失时不定位。
- 新增已导入会话的“只读刷新”。原生切换点击已绑定的可见联系人，保留扩展连接；读取后再次核对身份。旧 URL 不会覆盖已绑定的当前组件；只有 URL、消息中的链接或姓名仍不足以绑定身份。
- 现有拒绝、等待、需回复与转人工规则及发送确认保持有效，真实发送和两种 Auto 均未开启。
