# M3 标识关联与幂等验证记录

日期：2026-10-22。版本：0.3.3，ARM64。延续 [0.3.2 验证记录](m3.2-validation.md)，真实发送验收仍待完成。

## 修复内容

旧逻辑只按当前招聘人标识查询回复意图。页面从 UID 切换到明确关联过的另一业务标识后，同一条提问可能再次被标为待回复；刷新时标识字段变少，也可能覆盖原拒绝关联。

- 保留在已绑定页面上明确观察过的标识关系，并沿已有关系查询拒绝状态和发送记录；后续页面少提供字段时不删除历史关系。
- 首联锁和入站消息回复锁均覆盖同一招聘人的已知标识；确认已发送、结果不确定、人工确认未发并跳过的记录继续阻断重复。
- 已导入平台招呼的招聘人通过已知标识关联到其它岗位时，进入会话助手，阻断再次首联。
- 模型的已讲事实提示沿同一招聘人标识查询，减少换标识后重复介绍经历。模型输入仍只有必要提问、确认事实及事实 ID 提示。
- 提交前及编辑后再次读取均先核对精确目标身份；身份不符时不导入错误目标。标识关联不授予发送权限，不扩大用户选择的 Auto 范围。

关系只来自已绑定页面明确提供的业务标识。相同姓名、公司、消息链接或模型判断不用于合并身份。SQLite 仍为 v4，无结构迁移。

## 验证

新增回归首先在旧逻辑复现失败，修复后通过：刷新字段减少仍保留拒绝、跨标识链保持拒绝、同一提问跨标识不重复回复、新提问继续携带已讲事实提示、重启后的不确定回复仍去重、另一个岗位的同一招聘人不重复首联、平台招呼转已有会话流程。另有相同姓名/公司但无标识关联的独立招聘人对照，避免误合并。

- `npm run check`：类型检查、**66/66 测试**、Worker 和 UI 生产构建通过。
- `npm run smoke:m3`：匿名会话草稿、事实不足转人工及发送阻断通过，浏览器写入为 0。
- `npm run verify:ui:m3`、`npm run verify:ui:chat`：首联两条确认、事实回复确认、等待/拒绝分类、Auto 范围与去重、人工核验、急停及明暗/窄窗通过。全部使用隔离数据库、匿名模型和模拟发送。
- `npm run desktop:build -- --ci`、`npm run verify:installer`：App/DMG 构建、只读挂载复制、ad-hoc 签名结构、捆绑 Node、解析、MCP、GUI 授权边界、单实例、退出及中断重启通过。
