# 0.4.1：JD 稳定性与审核队列恢复

日期：2026-10-22。版本：0.4.1 / ARM64。此轮不执行真实发送。

## 问题与修复

用户在审核队列发现最终候选再次显示“版本已失效”，无法进入发送前确认。只读对比同一岗位的备份与当前 JD，差异仅为插入的 `BOSS直聘`、`kanzhun` 和 `boss` 文字，正文使用 `textContent` 导致隐藏标签也参与 JD 哈希。事实版本仍为冻结 v44，匹配规则与发送配置没有改变。

详情提取改用渲染后的 `innerText`，保留真实可见的正文和换行。没有通过全局删除品牌词或忽略 JD 变化来放宽校验。新增测试验证：隐藏标签变化不影响正文；相同品牌词可作为真实可见要求保留；真实可见要求修改仍产生不同正文。

审核队列的失效记录新增“重新匹配并生成草稿”，复用当前事实、规则及模型准备新草稿，回到 PENDING，旧审核不会自动恢复。“检查发送条件”改为“发送前检查”，页面明确说明只打开确认窗口，最终“确认发送”才会提交消息。
